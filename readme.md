# Kingdom of Winners (KoW) Tracker & Event Planner

Интеллектуальная веб-система для автоматизации учета офицеров, распределения призовых мест на событиях, конструктора сезонов альянса и координации составов игроков в игре Kingdom of Winners / Sea War: Raid.

---

## ⚡ Быстрый старт на сервере (В один клик)

Для быстрого развертывания на любом Linux-сервере (Ubuntu, Debian, CentOS, AlmaLinux, Fedora) предусмотрен автоматизированный скрипт мастера развертывания:

```bash
git clone <URL_РЕПОЗИТОРИЯ> kow-tracker
cd kow-tracker
chmod +x deploy.sh
./deploy.sh
```

**Что делает скрипт `deploy.sh`:**
1. Проверяет наличие Docker и Docker Compose (при отсутствии — предлагает и выполняет автоматическую установку официального Docker Engine).
2. Создает безопасную структуру каталогов хранения данных (`./data`) и бэкапов (`./backups`) с правами `750`.
3. Создает production-конфигурацию `.env` из шаблона `.env.example`.
4. Собирает оптимизированный production-образ и запускает контейнер в фоновом режиме.
5. Проводит проверку доступности (Healthcheck HTTP 200).
6. **Автоматически настраивает Nginx и выпускает бесплатный SSL-сертификат Let's Encrypt (HTTPS)** при указании домена или в интерактивном мастере (включая открытие портов 80/443 в UFW, генерацию конфига и автопродление сертификатов через `certbot.timer`).
7. Выводит безопасные внешние адреса доступа (`https://ваш-домен`) и начальные учетные данные администратора.

> **Примеры запуска:**
> ```bash
> # Интерактивный мастер (с вопросом о домене и SSL):
> ./deploy.sh
> 
> # Развертывание под ключ с готовым доменом и SSL в одну команду:
> ./deploy.sh --domain kow.myalliance.ru --email admin@myalliance.ru
> 
> # Развертывание только Docker-контейнера без настройки Nginx:
> ./deploy.sh --skip-ssl
> 
> # Тихий режим автоматизации (CI/CD):
> ./deploy.sh --auto --skip-ssl
> ```

## 🚀 Варианты ручного развертывания

### Вариант 1: Docker Compose (Рекомендуется для продакшна)

**Требования:** Docker Engine 24+ и Docker Compose v2.

1. **Клонирование и настройка окружения:**
   ```bash
   cp .env.example .env
   ```
2. **Запуск сервиса в фоновом режиме:**
   ```bash
   docker compose up -d --build
   ```
3. **Проверка работы и логов:**
   ```bash
   docker compose ps
   docker compose logs -f
   ```
4. **Доступ:** откройте `http://IP_СЕРВЕРА:3000` в браузере.

База данных SQLite сохраняется на хост-машине в каталоге `./data/kow.db` благодаря volume mapping (`./data:/app/data`). Данные **не теряются** при перезапусках, пересборках или обновлениях контейнера.

Остановка контейнера:
```bash
docker compose down
```

---

### Вариант 2: Запуск без Docker на чистом Node.js

**Требования:** Node.js 22 LTS (используются нативные модули `node:sqlite`, `node:crypto`, `node:http`, внешние npm-зависимости отсутствуют).

1. **Запуск сервиса:**
   ```bash
   npm start
   # или напрямую:
   node server.js
   ```
2. **Кастомный порт или путь к БД (при необходимости):**
   ```bash
   PORT=8080 DB_PATH=/var/lib/kow/kow.db node server.js
   ```

## 🛠️ Руководство по развертыванию в продакшн (Production Deployment Guide)

### 1. Архитектура и обязательность HTTPS / SSL

> [!IMPORTANT]
> **HTTPS обязателен для мобильных устройств!**
> Более 90% игроков пользуются трекером со смартфонов и планшетов (iOS Safari, Android Chrome). Браузерная технология **PWA (Progressive Web App, Service Worker, оффлайн-кэширование, возможность добавить на главный экран)** на внешних доменах блокируется браузерами при использовании незащищенного протокола HTTP. 
> Для работы мобильного приложения необходимо привязать домен и настроить SSL-сертификат.

Рекомендуемая схема:
```
[Мобильные телефоны / Браузеры]
              │
         HTTPS (Порт 443)
              ▼
    [Nginx Reverse Proxy]  ◄── SSL Certbot (Let's Encrypt)
              │
         HTTP (Порт 3000, 127.0.0.1)
              ▼
   [Docker: KoW Tracker Node.js]
              │
       [SQLite: ./data/kow.db]
```

---

### 2. Настройка Nginx Reverse Proxy и Let's Encrypt

1. **Установите Nginx и Certbot:**
   ```bash
   sudo apt update
   sudo apt install -y nginx certbot python3-certbot-nginx
   ```

2. **Привяжите порт Docker только к локальному интерфейсу `127.0.0.1`:**
   В файле `.env`:
   ```ini
   BIND_IP=127.0.0.1
   PORT=3000
   ```
   Примените: `docker compose up -d`

3. **Скопируйте готовый конфиг Nginx из репозитория:**
   ```bash
   sudo cp deploy/nginx/kow-tracker.conf /etc/nginx/sites-available/kow-tracker.conf
   ```
   Откройте файл `sudo nano /etc/nginx/sites-available/kow-tracker.conf` и укажите ваш реальный домен вместо `your-domain.com`.

4. **Активируйте сайт и проверьте конфигурацию:**
   ```bash
   sudo ln -s /etc/nginx/sites-available/kow-tracker.conf /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
   ```

5. **Выпустите бесплатный SSL-сертификат:**
   ```bash
   sudo certbot --nginx -d your-domain.com
   ```
   Сертификат будет автоматически продлеваться службой certbot.

---

### 3. Сетевая безопасность и Firewall (UFW)

Настройте фаервол сервера так, чтобы снаружи были открыты только веб-порты 80, 443 и SSH, а внутренний порт 3000 был недоступен из интернета:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status
```

Ограничьте права доступа к каталогу базы данных на сервере:
```bash
chmod 750 ./data
chmod 640 ./data/kow.db 2>/dev/null || true
```

---

### 4. Автоматический запуск через systemd (для развертывания без Docker)

Если вы запускаете проект без Docker, настройте системную службу systemd для автозапуска при загрузке сервера и перезапуска при сбоях:

1. Скопируйте готовый unit-файл:
   ```bash
   sudo cp deploy/systemd/kow-tracker.service /etc/systemd/system/
   ```
2. Отредактируйте пути к директории и Node.js (`sudo nano /etc/systemd/system/kow-tracker.service`).
3. Включите и запустите службу:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now kow-tracker
   sudo systemctl status kow-tracker
   ```

---

### 5. Автоматическое резервное копирование базы данных (Cron Backup)

В проекте есть автономный скрипт горячего бэкапа SQLite с ротацией архивов за 14 дней:
`deploy/scripts/backup.sh`.

Чтобы настроить автоматическое резервное копирование каждую ночь в 03:00:
```bash
crontab -e
```
Добавьте строку:
```cron
0 3 * * * /opt/kow-tracker/deploy/scripts/backup.sh > /dev/null 2>&1
```

Архивы бэкапов сохраняются в `./backups/kow_backup_YYYYMMDD_HHMMSS.db.tar.gz`.

---

### 6. Безопасное обновление сервиса (Upgrade Flow)

Все изменения схемы SQLite-базы данных обратно совместимы и мигрируют автоматически при старте сервера.

Для обновления сервиса на сервере без потери данных:
```bash
cd /opt/kow-tracker

# 1. Получение свежей версии кода
git pull origin master

# 2. Пересборка и перезапуск контейнера
docker compose up -d --build

# 3. Проверка успешного старта
docker compose logs --tail=50
```

## 🔐 Доступ по умолчанию и безопасность

При первом старте система автоматически инициализирует SQLite базу и создает учетную запись администратора (R5):

- **Логин**: `admin`
- **Пароль**: `admin123`
- **Роль**: `R5` (Лидер альянса — полный доступ)

> [!CAUTION]
> **Обязательно смените пароль учетной записи `admin` сразу после первого входа!** Это можно сделать в Личном кабинете или в разделе «Пользователи».

## 👥 Ролевая модель доступа (RBAC)

1. **R5 (Глава альянса / Администратор)**:
   - Полный доступ ко всем разделам.
   - Управление ролями участников (повышение R3 до R4/R5).
   - Пакетное создание сезонов альянса в Конструкторе сезонов.
   - Управление Каталогом офицеров, типами событий и шкалой уровней VIP.
   - Полный JSON Экспорт и Импорт базы данных.
2. **R4 (Чиновник / Военком)**:
   - Одобрение и отклонение регистраций новых бойцов.
   - Управление реестром секторов альянса, смена владельцев баз.
   - Конструктор сезонов, создание событий, запуск алгоритма **Smart AutoPick** с учетом Fair Play.
   - Фиксация результатов событий.
3. **R3 (Боец / Игрок)**:
   - Изолированный доступ: видит только **Календарь** и свой **Личный кабинет**.
   - Прямой доступ к админским разделам через API строго блокируется (`403 Forbidden`).
   - Поддержка мульти-аккаунтов: переключение между своими секторами/базами без перезагрузки.
   - Подача заявок на события от любой из своих баз.
   - Склад и Smart Scanner скриншотов профиля и склада.
