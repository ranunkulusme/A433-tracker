## 1. Контекст и цели

На основе замечаний и требований пользователя:
1. **Каталог офицеров на панели**:
   - Вывести раздел «Каталог офицеров» в боковую панель навигации трекера.
   - Дать возможность офицерам альянса (Р4/Р5) просматривать, добавлять, редактировать и удалять офицеров каталога.
2. **Очистка каталога и отключение авто-восстановления**:
   - При удалении всех офицеров они ранее заново восстанавливались при перезапуске сервера из-за авто-сидинга в `initDb()`.
   - Необходимо отключить авто-восстановление и очистить текущий каталог офицеров, так как старые данные не соответствуют действительности.
3. **Параметры подготовки офицера**:
   - Медали до подготовки (`medals_before_training`): базовое значение по умолчанию **480**.
   - Медали подготовки (`medals_training`): базовое значение по умолчанию **900**.
   - Всего медалей (`medals_total`): вычисляется как точная сумма `medals_before_training + medals_training` (по умолчанию `480 + 900 = 1380`). При изменении любого слагаемого сумма пересчитывается автоматически.
   - Курс купонов на 1 медаль (`coupon_per_puzzle`): например, 720 на S8, 600 на S7.
   - Курс купонов готовности звезды (`star_coupon_cost`): количество купонов готовности звезды за пакет 110 звёзд (например, 360 на S8, 300 на S7).
   - Типы войск ограничены списком: `['Танк', 'Пехота', 'ПТ-Сау', 'Горнизон', 'Осада']`.
4. **OCR-сканер магазина обмена со скриншота**:
   - Сканирование скриншота магазина обмена (где отображаются сезон S7/S8, портреты, имена офицеров, стоимость медалей и звёзд).
   - Распознавание имени, сезона, стоимости обмена медали и звёзд, предзаполнение базовых медалей (480 и 900), выбор типа войск и импорт в каталог в один клик.
5. **Настройка шкалы уровней VIP**:
   - В текущей версии для VIP 14 ошибочно требовалось 1 500 000 очков из-за захардкоженной приблизительной шкалы.
   - В игре для VIP 14 требуется **750 000** очков.
   - Создается динамическая таблица `vip_tiers` в базе данных с возможностью просмотра и редактирования каждого уровня (1–30) через модальное окно настроек VIP для офицеров Р4/Р5.

## 2. Архитектура и база данных (SQLite)

### 2.1. Таблица `vip_tiers`
```sql
CREATE TABLE IF NOT EXISTS vip_tiers (
  level INTEGER PRIMARY KEY,
  points INTEGER NOT NULL DEFAULT 0,
  daily_puzzles REAL NOT NULL DEFAULT 0,
  daily_chests REAL NOT NULL DEFAULT 1
);
```
- Инициализация/миграция в `initDb()`:
  - Если таблица пуста, заполняется 30 уровней.
  - Уровень 14 строго устанавливается в `750000` очков, `3` ежедневных пазла, `1` сундук.
  - Уровни 1..13 плавно интерполируются к 750 000:
    - L1: 0, L2: 200, L3: 700, L4: 2500, L5: 6000, L6: 15000, L7: 35000, L8: 75000, L9: 130000, L10: 220000, L11: 340000, L12: 480000, L13: 600000, L14: 750000.
- Методы `db.js`:
  - `getVipTiers()`: возвращает список отсортированный по `level ASC`.
  - `setVipTiers(tiers)`: валидация и пакетный `REPLACE INTO vip_tiers` в транзакции.

### 2.2. Таблица `officer_catalog`
- Новые/обновленные поля:
  - `star_coupon_cost INTEGER NOT NULL DEFAULT 360`
  - `medals_before_training INTEGER NOT NULL DEFAULT 480`
  - `medals_training INTEGER NOT NULL DEFAULT 900`
  - `medals_total INTEGER NOT NULL DEFAULT 1380`
  - `type TEXT NOT NULL` (проверяется допустимость `['Танк', 'Пехота', 'ПТ-Сау', 'Горнизон', 'Осада']`)
- Миграция схемы:
  - Безопасное добавление колонки `star_coupon_cost` через `ALTER TABLE` при отсутствии.
  - Обновление дефолтов в `initDb()`.
- Отключение авто-сидинга:
  - Удален блок принудительного перезаписывания `COMMUNITY_OFFICERS` в `initDb()`.
  - Выполнен разовый `DELETE FROM officer_catalog` для очистки устаревших записей.
  - Метод `saveCatalogItem(db, item)` валидирует поля и вычисляет `medals_total = medals_before_training + medals_training`.

## 3. Серверный слой REST API (`server.js`)

1. **VIP Tiers**:
   - `GET /api/vip-tiers`: возвращает `200` с массивом уровней VIP. Доступно всем авторизованным пользователям.
   - `PUT /api/vip-tiers`: принимает `{ tiers: [...] }`, валидирует `level` (1..30), `points` (>= 0), `dailyPuzzles` (>= 0). Доступно только `['r4', 'r5']`. Возвращает `200` с обновленными уровнями.
2. **Catalog**:
   - `GET /api/catalog`: возвращает список офицеров каталога.
   - `POST /api/catalog`: создание офицера с полями `name`, `type`, `generation`, `couponPerPuzzle`, `starCouponCost`, `medalsBeforeTraining`, `medalsTraining`, `upgradeType`. Доступно `['r4', 'r5']`.
   - `PUT /api/catalog/:id`: обновление офицера. Доступно `['r4', 'r5']`.
   - `DELETE /api/catalog/:id`: удаление офицера (с проверкой `canDeleteOfficer`). Доступно `['r4', 'r5']`.
   - `POST /api/catalog/batch`: пакетное создание/обновление распознанных офицеров со скриншота магазина. Доступно `['r4', 'r5']`.

## 4. Клиентская логика и OCR (`logic.js`, `ocr.js`)

1. **Типы войск (`logic.js`)**:
   - Экспорт `OFFICER_TYPES = ['Танк', 'Пехота', 'ПТ-Сау', 'Горнизон', 'Осада']`.
2. **Расчеты медалей**:
   - `calculateTotalMedals(beforeTraining, training)`: чистая функция, возвращающая `Math.max(0, beforeTraining) + Math.max(0, training)`.
3. **Расчеты VIP**:
   - `calculateVipDeficit`: принимает кастомный массив `vipTiers` (из API/БД), используя его вместо жестко зашитого массива.
   - `dailyRewards`: использует `vipTiers` для вычисления ежедневных пазлов.
4. **OCR магазина обмена (`logic.js` + `ocr.js`)**:
   - `parseExchangeShopScreenshotText(text)`:
     - Определение сезона/поколения: `Обмен на медали офицера, сезон (\d+)` или бейджи `S(\d+)`.
     - Извлечение офицеров: имя офицера, стоимость пазла (купоны), стоимость 110 звезд (купоны).
     - Возвращает массив объектов:
       ```javascript
       {
         name: 'По',
         generation: 8,
         couponPerPuzzle: 720,
         starCouponCost: 360,
         medalsBeforeTraining: 480,
         medalsTraining: 900,
         medalsTotal: 1380,
         type: 'Танк' // дефолт с возможностью смены
       }
       ```

## 5. Пользовательский интерфейс (`index.html`, `app.js`, `style.css`)

1. **Навигация**:
   - Добавлен пункт в сайдбар: `🎖️ Каталог офицеров`.
   - При переходе на `#catalog` открывается страница каталога секторов/офицеров.
2. **Экран каталога (`#page-catalog`)**:
   - Шапка:
     - Кнопка «+ Добавить офицера» (Р4/Р5) -> `#modal-catalog-officer`.
     - Кнопка «📷 Распознать из магазина» (Р4/Р5) -> `#modal-exchange-ocr`.
     - Кнопка «⭐ Настройка шкалы VIP» (Р4/Р5) -> `#modal-vip-tiers`.
   - Таблица офицеров:
     - Бейдж поколения (`S8`, `S7`), имя, тип войск (`badge-type`), медали (до подготовки 480, подготовка 900, всего 1380), курс купонов (пазл 720, 110★ за 360), действия.
     - Empty-state: при пустом каталоге отображается плашка «Каталог пуст. Добавьте офицеров вручную или распознайте со скриншота магазина обмена».
3. **Модальное окно редактирования офицера (`#modal-catalog-officer`)**:
   - Поля: Имя, Тип (select из 5 типов), Сезон (число), Купоны на 1 медаль, Купоны за 110 звёзд, Медали до подготовки, Медали подготовки, Всего медалей (динамическое расчетное поле).
4. **Модальное окно распознавания магазина (`#modal-exchange-ocr`)**:
   - Drag & Drop / выбор файла / вставка из буфера обмена (`Ctrl+V` / `Cmd+V`).
   - Прогресс-бар OCR.
   - Предпросмотр найденных офицеров в виде таблицы с возможностью скорректировать поля и типы войск.
   - Кнопка «Добавить всех в каталог».
5. **Модальное окно настройки шкалы VIP (`#modal-vip-tiers`)**:
   - Таблица 1..30 с инпутами очков и ежедневных пазлов.
   - Акцент на VIP 14 (750 000).
   - Кнопка «Сохранить шкалу VIP».
