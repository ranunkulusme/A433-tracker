**Дата создания:** 2026-10-24  
**Дата обновления:** 2026-10-25  
**Статус:** Готово к реализации  
**Целевая ветка разработки по GitFlow:** `feature/community-data-integration` (ответвление от `master` v3.0.0)

## 1. Контекст текущего состояния проекта (Status Quo v3.0.0)

В рамках релиза `v3.0.0` проект совершил переход от автономного SPA (`localStorage`) к полноценному клиент-серверному стеку:
1. **Бэкенд:** Автономный HTTP-сервер на чистом Node.js (`server.js`, `node:http`, `node:crypto`) без внешних npm-зависимостей.
2. **База данных:** SQLite через нативный модуль `node:sqlite` (`db.js`, файл `data/kow.db` с автосозданием директории).
3. **Ролевая модель (RBAC):** Пользователи (`users`), сессии с токенами (`sessions`), роли `r5` (Глава), `r4` (Чиновники), `r3` (Рядовые в изолированном личном кабинете).
4. **Заявки на ивенты:** Таблица `event_registrations`, автоподбор с учетом желаемых мест (`smartAutoPickWithRegistrations`).
5. **Тестирование:** Полный набор модульных и интеграционных тестов (`logic.test.js`, `db.test.js`, `api.test.js`), запускаемый через `npm test`.

**Разрыв (Gap Analysis):**
Существующая база данных и сервер работают только с базовыми полями. Они не знают о навыках офицеров (5-5-5-5), очках VIP, способах прокачки офицеров (стандартные vs колесо/донат), кулдауне победителей в автоподборе и пресетах генерации расписания.

## 2. Архитектурные изменения по слоям

### 2.1. Слой данных и схема SQLite (`db.js`)

Необходимо обеспечить бесшовное обновление схемы существующей базы данных (`ALTER TABLE ... ADD COLUMN ...` с проверкой существования колонок):

1. **Таблица `players`:**
   - Добавить колонку: `vip_points INTEGER NOT NULL DEFAULT 0` (текущие очки VIP для расчета окупаемости следующего тира).
2. **Таблица `player_officers`:**
   - Добавить колонку: `skills_json TEXT NOT NULL DEFAULT '[1,1,1,1]'` (массив из 4 чисел в диапазоне 1..5).
3. **Таблица `officer_catalog`:**
   - Добавить колонку: `upgrade_type TEXT NOT NULL DEFAULT 'standard'` (`'standard'` — прокачка купонами и пазлами, `'special'` — эксклюзивные колесные/донатные офицеры).
   - Расширить сидирование начальных данных (`seedDemoData`): предзаполнить каталог реальными командирами Kiss of War (Gen 7–9, а также ключевые командиры Gen 1–6).
4. **Методы БД:**
   - `getPlayerById`, `updatePlayer`, `createPlayer`: поддержка сохранения и возврата `sector.vipPoints`.
   - `getPlayerOfficers`, `addPlayerOfficer`, `updatePlayerOfficer`: сериализация/десериализация `skills_json` в массив `skills: [s1, s2, s3, s4]`.
   - `getCatalogOfficers`, `saveCatalogOfficer`: поддержка `upgradeType`.
   - `exportKowJson` / `importKowJson`: полная поддержка новых полей с сохранением 100% совместимости с файлами формата `v2`/`v3`.

### 2.2. Математическое ядро и справочники (`logic.js`)

Модуль `logic.js` остаётся универсальным UMD-модулем, используемым как на бэкенде, так и на фронтенде:

1. **Расширенный реестр `COMMUNITY_OFFICERS`:**
   - **Gen 7–9 (Основная мета подготовки):** Генерал Рекс (Танк, Gen 7), Капитан Блэк (ПТ, Gen 7), Адмирал Нейтон (Пехота, Gen 8), Аврора (Гарнизон, Gen 8), Валькирия (Осада, Gen 9).
   - **Ключевые офицеры ранних поколений:** Ангел (Танк, Gen 2, Колесо), Халина (ПТ, Gen 2, Колесо), Бетти (Пехота, Gen 3, Колесо), Ева (Танк, Gen 2, Сильнейший Командир), Грейс (Танк, Gen 1, First Recharge), Джессика (Танк, Gen 1, VIP), Марджори (Пехота, Gen 1, VIP).
   - Для каждого офицера задаются `upgradeType: 'standard' | 'special'` и `couponPerPuzzle` (500 или 0).
2. **Шкала VIP и расчет окупаемости (`VIP_TIERS_DATA`, `calculateVipDeficit`):**
   - Точные пороги очков для уровней VIP 1–30:
     `[0, 200, 700, 2500, 6000, 15000, 35000, 75000, 150000, 300000, 500000, 750000, 1000000, 1500000, 2500000, ...]`.
   - Функция:
     ```javascript
     calculateVipDeficit({ currentLevel, currentPoints, targetLevel })
     // Возвращает: { pointsNeeded, dailyPuzzlesIncrease, targetLevel, daysToTargetAtCurrentRate }
     ```
3. **Сетка прокачки навыков 5-5-5-5 (`SKILL_UPGRADE_COSTS`, `calculateSkillMedalsProgress`):**
   - Распределение 690 медалей до подготовки по 4 навыкам:
     - Навык 1: 10 + 20 + 30 + 40 = 100
     - Навык 2: 20 + 40 + 60 + 80 = 200
     - Навык 3: 30 + 50 + 70 + 90 = 240
     - Навык 4: 10 + 30 + 50 + 60 = 150 (суммарно ровно 690 медалей).
   - Функция:
     ```javascript
     calculateSkillMedalsProgress(skills = [1, 1, 1, 1])
     // Возвращает: { spentMedals, remainingMedals, isMaxSkills }
     ```
4. **Справочник мета-связок (`OFFICER_PAIRINGS`, `getRecommendedPairings`):**
   - Связки офицеров по родам войск (Танк, ПТ, Пехота, Гарнизон) с указанием ролей (Открытое поле, Ралли, Оборона).
5. **Пресеты ивентов и генератор расписания (`EVENT_PRESETS`, `generateSeasonSchedule`):**
   - Пресет «Король Войны» (King of War, 14 дней).
   - Пресет «Сильнейший Командир» (Mightiest Commander, 28 дней).
   - Функция генерации дат `generateSeasonSchedule({ startDate, cyclesCount, presetId })`.
6. **Правила справедливости (Fair Play) в автоподборе:**
   - Модификация `smartAutoPickWithRegistrations`:
     - Добавление опционального параметра `recentWinners: [playerId, ...]`.
     - Если игрок побеждал (занимал 1-е место) в предыдущем ивенте того же типа, к его баллу в скоринге применяется штрафной коэффициент кулдауна, если есть альтернативные подходящие кандидаты с дефицитом.

### 2.3. Серверный REST API (`server.js`)

1. **Эндпоинт `/api/my-profile` (Личный кабинет Р3):**
   - `PUT /api/my-profile`: санитизация и сохранение `sector.vipPoints`.
   - `POST /api/my-profile/officers` и `PUT /api/my-profile/officers/:id`: санитизация и сохранение массива `skills` (4 целых числа от 1 до 5).
2. **Эндпоинт каталога `/api/catalog` (Р4/Р5):**
   - `POST /api/catalog` и `PUT /api/catalog/:id`: сохранение поля `upgradeType`.
3. **Новый эндпоинт `/api/events/schedule-season` (Р4/Р5):**
   - Метод: `POST`.
   - Тело запроса: `{ presetId, startDate, cyclesCount }`.
   - Генерирует в БД запланированные события на основе `generateSeasonSchedule` и создаёт соответствующий тип ивента при необходимости.
4. **Обновление автоподбора `POST /api/events/:id/autopick`:**
   - Сервер автоматически извлекает из БД список победителей 1-го места в предыдущих ивентах этого же типа (`getRecentWinners(eventTypeId, limit = 2)`).
   - Передает `recentWinners` в `smartAutoPickWithRegistrations`.

### 2.4. Клиентский интерфейс (`app.js`, `index.html`, `style.css`)

1. **Личный кабинет игрока (`my_cabinet`) и карточка игрока:**
   - Ввод текущих очков VIP (`#fp-vip-points`) с динамическим расчетом дефицита до следующего уровня и подсказкой прибавки пазлов в день.
   - Сетка из 4 навыков для каждого офицера: интерактивные кнопки/селекторы `1..5` с индикатором прогресса по медалям (из 690).
2. **Каталог и карточка офицера:**
   - Бейджи типа прокачки (`Купонный 500/1` vs `Только пазлы`).
   - Блок «Рекомендуемые связки командиров» на основе `getRecommendedPairings`.
3. **Календарь ивентов:**
   - Кнопка «⚡ Создать сезон по шаблону» в шапке календаря (открывает модальное окно выбора пресета и начальной даты).
   - Отображение статуса кулдауна в карточке назначения автоподбора (бейдж «Кулдаун после прошлого Топ-1»).

## 3. Требования к безопасности, тестированию и качеству

1. **Строгое соблюдение GitFlow:**
   - Работа ведется в отдельной ветке `feature/community-data-integration`.
   - Запрет прямых коммитов в `master`.
   - Релиз оформляется через `release/v3.1.0` с повышением версии в `package.json` и фиксацией в `CHANGELOG.md`.
2. **TDD и 100% прохождение тестов:**
   - `node logic.test.js`: юнит-тесты формул навыков, VIP, генерации расписания, кулдауна автоподбора.
   - `node db.test.js`: тесты миграции колонок `skills_json`, `vip_points`, `upgrade_type`, CRUD-операций и экспорта/импорта.
   - `node api.test.js`: интеграционные тесты RBAC для новых полей профиля и эндпоинта генерации сезона.
   - Проверка синтаксиса: `node -c app.js && node -c server.js`.
3. **Обратная совместимость:**
   - Любые базы данных, созданные в версии v3.0.0, должны автоматически и прозрачно обновляться при вызове `initDb()`.
   - Импорт старых JSON-файлов `kow_v2` / `kow_v3` не должен приводить к ошибкам или потере данных.
