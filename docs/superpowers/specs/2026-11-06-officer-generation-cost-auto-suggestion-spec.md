# Спецификация: Умная автоподстановка стоимости медали офицера в Каталоге

## 1. Контекст и проблема
При добавлении нового офицера в каталог гильдии администраторам (Р4 / Р5) необходимо указывать базовую стоимость 1 медали в купонах (`coupon_per_puzzle`).
В игре стоимость медалей растет от сезона к сезону по экспоненциальному закону (удвоение с коэффициентом $k \approx 2.076 \dots 2.083$ и округлением в большую сторону).
Ручной ввод требует знания формул игры и может приводить к ошибкам или несогласованности расчётов на складе.

## 2. Требования

### 2.1 Математический модуль (`logic.js`)
- Экспортировать чистую функцию `suggestOfficerPuzzleCost({ generation, type, catalog = [], roundUpStep = 50 })`.
- Использовать подтвержденную цепочку реальных данных игры:
  - Танки: S2=20, S3=28, S4=56, S5=116, S6=240, S7=500.
  - Пехота: S6=289, S7=600.
- Если в `catalog` найден офицер того же типа войск `type` и поколения `generation - 1` с ценой $C_{prev} > 0$:
  - Если известно и поколение $generation - 2$ с ценой $C_{prev2} > 0$, вычисляется динамический коэффициент: $k = C_{prev} / C_{prev2}$.
  - Иначе применяется базовый коэффициент $k = 2.0761$.
- Иначе (если офицеров предыдущего поколения в каталоге нет):
  - Поиск в эталонной таблице поколений.
- Округление в большую сторону с шагом `roundUpStep` (по умолчанию 50):
  $$\text{suggestedCost} = \lceil (C_{prev} \times k) / 50 \rceil \times 50$$
  - Танк S8: $500 \times 2.0833 \approx 1041.67 \to 1050$.
  - Пехота S8: $600 \times 2.0761 \approx 1245.67 \to 1250$.
- Возвращаемая структура:
  ```json
  {
    "suggestedCost": 1050,
    "baseGeneration": 7,
    "baseCost": 500,
    "baseType": "Танк",
    "multiplier": 2.0833,
    "hintText": "..."
  }
  ```

### 2.2 Пользовательский интерфейс (`index.html`, `app.js`, `style.css`)
- В модальное окно `#modal-officer` под полем `#fo-coupon-per-puzzle` добавлен контейнер подсказки `#fo-coupon-hint`.
- При создании нового офицера (`openOfficerCatalogModal(null)`):
  - При открытии окна и при любом изменении `#fo-generation` (поколение) или `#fo-type` (тип войск):
    - Вызывается авторасчёт `suggestOfficerPuzzleCost`.
    - Если пользователь не изменял инпут стоимости вручную (`!isCouponManuallyEdited`), поле `#fo-coupon-per-puzzle` автоматически заполняется значением `suggestedCost`.
    - Отображается информационный бейдж с пояснением (источник, поколение, коэффициент).
  - Если пользователь ввёл значение вручную, автозамена прекращается, но подсказка мягко показывает рекомендацию с возможностью вернуть авторасчёт.
- При редактировании существующего офицера:
  - Исходная стоимость офицера не перезаписывается.
