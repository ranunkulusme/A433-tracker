## 1. Цели, Контекст и Ценность (Intent & Why)

### 1.1. Контекст
Более 90% игроков альянса заходят в KoW Tracker со смартфонов (iOS Safari и Android Chrome) непосредственно во время игры или находясь в пути. При этом качество мобильного интернета часто бывает нестабильным (поездки, слабый сигнал), а открывать сайт каждый раз через вкладки браузера неудобно.

### 1.2. Цели (Goals)
1. **Нативный мобильный опыт (PWA):**
   - Возможность установить KoW Tracker на домашний экран смартфона в 1 клик.
   - Запуск в полноэкранном режиме (`standalone`) без адресной строки и кнопок браузера.
   - Фирменная векторная иконка приложения и сплеш-скрин с темной темой (`#0f172a`).
2. **Мгновенная загрузка оболочки (Offline Shell):**
   - Service Worker (`sw.js`) кэширует статическую оболочку приложения (`index.html`, `style.css`, `app.js`, `logic.js`, иконки, манифест).
   - Приложение открывается мгновенно даже при полном отсутствии подключения к сети.
3. **Оффлайн-мутации и фоновая синхронизация (Outbox Queue):**
   - Игрок в оффлайне может изменять уровни офицеров, навыки, запасы купонов и подавать заявки на ивенты.
   - Изменения применяются **оптимистично** в интерфейсе сразу же (без задержек и ошибок).
   - Запросы на мутации сохраняются в локальную очередь `syncQueue` (Outbox).
   - При появлении сети очередь автоматически воспроизводится на сервер в порядке поступления (FIFO), после чего данные синхронизируются.
4. **Прозрачная индикация статуса сети в UI:**
   - Ненавязчивый бейдж в шапке приложения:
     - Оффлайн: `🟡 Оффлайн (N изменений в очереди)`.
     - Синхронизация: `🔄 Синхронизация...`.
     - Онлайн: `🟢 Онлайн (все данные сохранены)`.
5. **Поддержка 100% мобильных устройств:**
   - Полная работоспособность на **iPhone/iPad (iOS Safari)** и **Android (Chrome)**.

### 1.3. Не-цели (Non-Goals)
- Использование W3C Background Sync API (`SyncManager`), так как он не поддерживается на iOS Safari.
- Оффлайн-выполнение сложных административных операций гильдии (запуск автоподбора состава, генерация сезонного календаря) — такие операции требуют живого подключения к серверу.

## 2. Варианты реализации (Approaches)

### Рассмотренные варианты:

* **Вариант 1 (Выбранный): Клиентская очередь Outbox + Service Worker для кэширования статики**
  - *Архитектура:* Service Worker кэширует статику по стратегии Stale-While-Revalidate. Запросы к API `/api/*` перехватываются на уровне клиента в обертке `apiFetch`. При сбое сети мутация личного кабинета записывается в `syncQueue` (в `localStorage`), применяется оптимистично к UI, а слушатели событий `window.addEventListener('online')` и фоновый таймер сбрасывают очередь на сервер при появлении связи.
  - *Трейдоффы:* Гарантирует 100% работу на iPhone и Android без внешних зависимостей. Синхронизация происходит при открытом приложении или возвращении на экран.
* **Вариант 2: Нативный Background Sync API внутри Service Worker**
  - *Архитектура:* Регистрация `sync.register('sync-mutations')` в Service Worker.
  - *Трейдоффы:* Не работает на устройствах Apple (iOS Safari не поддерживает `SyncManager`), что сделало бы оффлайн-режим неработоспособным для пользователей iPhone. Отклонен.

## 3. Детальные архитектурные решения (Builder Decisions)

### 3.1. Холодный старт (Cold Start) в оффлайне и сохранение сессии
* **Решение:** Профиль текущего авторизованного пользователя (`kow_user`) кэшируется в `localStorage` рядом с токеном `kow_token`.
* При старте приложения в оффлайне (`!navigator.onLine` или сетевой сбой при вызове `/api/auth/me`):
  - Токен **не сбрасывается**. Приложение инициализируется в оффлайн-режиме под кэшированным пользователем.
  - Очистка токена и переход на экран логина происходят **только при явном ответе сервера 401 Unauthorized**.
  - Если после восстановления связи сервер ответил `401`, очередь Outbox замораживается (не удаляется), пользователю выводится модальное окно повторного входа, после чего очередь досылается.

### 3.2. Область действия оффлайн-мутаций (Scope)
* **Решение:** Очередь Outbox обрабатывает мутации данных личного кабинета игрока (Р3):
  - `PUT /api/my-profile` (обновление сектора, запасов, офицеров, навыков).
  - `POST /api/my-profile/officers` и `PUT /api/my-profile/officers/:id` (добавление/правка офицеров).
  - `DELETE /api/my-profile/officers/:id` (удаление офицера).
  - `POST /api/events/:id/registrations` и `DELETE /api/events/:id/registrations` (подача/отзыв заявки на ивент).
* Административные действия Р4/Р5 (генерация расписания `/api/events/schedule-season`, автоподбор `/api/events/:id/autopick`, модерация `/api/users/:id/approve`, экспорт/импорт) требуют живого соединения. При клике в оффлайне выводится предупреждение: *«Это действие доступно только при подключении к сети»*.

### 3.3. Обработка ошибок при воспроизведении очереди (4xx / 5xx)
* **Решение (Drop, Notify & Overwrite):**
  - Если при воспроизведении очереди запрос падает с ошибкой `400/404/409` (например, событие было отменено до того, как оффлайн-заявка дошла до сервера):
    - Сбойная операция исключается из очереди (защита от Head-of-Line blocking).
    - Пользователю выводится уведомление toast: *«Не удалось применить оффлайн-изменение: [текст ошибки]»*.
    - После завершения очереди вызывается `loadDataFromServer()`, перезаписывающий локальное состояние подтвержденными данными сервера.

### 3.4. Генерация идентификаторов сущностей
* **Решение:** Клиент генерирует `id` создаваемых офицеров в оффлайне по шаблону `po-${Date.now()}-${Math.random().toString(36).slice(2, 7)}`.
* Бэкенд в `db.addPlayerOfficer` уже поддерживает и сохраняет переданный `id`, что исключает необходимость подмены ID в очереди зависимых запросов.

### 3.5. Модель разрешения конфликтов (LWW)
* **Решение:** Последовательное воспроизведение очереди на клиенте (FIFO). Поскольку каждый игрок управляет исключительно собственным личным кабинетом, последнее сохраненное локально действие игрока отправляется последним и обновляет запись на сервере.

## 4. Компоненты системы

### 4.1. Web App Manifest и иконки (`manifest.json`)
* Файл `manifest.json`:
  ```json
  {
    "name": "KoW Officer Tracker",
    "short_name": "KoW Tracker",
    "description": "Трекер развития офицеров и планирования ивентов гильдии Kiss of War",
    "start_url": "/",
    "display": "standalone",
    "orientation": "portrait-primary",
    "background_color": "#0f172a",
    "theme_color": "#0f172a",
    "icons": [
      { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
      { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable" }
    ]
  }
  ```
* Генерация иконок 192×192 и 512×512 в `icons/`.
* Мета-теги в `index.html`: `theme-color`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `apple-touch-icon`.

### 4.2. Service Worker (`sw.js`)
* Кэширование статики (*Stale-While-Revalidate*): `/`, `index.html`, `style.css`, `app.js`, `logic.js`, `manifest.json`, иконки.
* Пропуск запросов `/api/*` напрямую в сеть с обработкой на клиенте.
* `skipWaiting()` и `clients.claim()` для быстрого обновления версий кэша.

### 4.3. Клиентская очередь Outbox (`app.js`)
* Очередь хранится в `localStorage.getItem('kow_outbox_queue')`.
* Слушатели: `online`, `focus`, таймер каждые 30 секунд.
* Функция `flushOutboxQueue()`: последовательная отправка с токеном авторизации, удаление успешных элементов, вызов `loadDataFromServer()` по завершении.

### 4.4. UI-компоненты
* **Индикатор сети (Network Status Pill):** в шапке отображает актуальное состояние соединения и счетчик очереди.
* **Кнопка установки (PWA Install Button):** перехват `beforeinstallprompt` на Android и аккуратная инструкция для iOS Safari («Поделиться» → «На экран „Домой“»).
