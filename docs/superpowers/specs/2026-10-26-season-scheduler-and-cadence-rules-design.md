# Дизайн-документ: Комплексный конструктор сезонов и настраиваемые правила циклов ивентов

**Дата создания:** 2026-10-26  
**Целевой релиз:** `v3.6.0`  
**Ветка:** `feature/season-scheduler-and-cadence-rules`  
**Статус:** На согласовании (Draft)

---

## 1. Контекст и цели (Intent & Why)

В текущей версии KoW Tracker при создании сезона в модальном окне генератора расписания использовались устаревшие и не соответствующие реальной игре шаблоны:
1. «Сильнейший Командир» — такого ивента в игре не существует.
2. «Король Войны» создавался жесткими отрезками по 7 дней активности и 7 дней перерыва, тогда как в игре он длится всего 2 дня (вторник–среда).
3. Отсутствовали реальные события, дающие купоны офицера: «Мощные силы» (3 дня: суббота–понедельник) и «Сила времени» (трата ускорителей на альтернативной неделе).
4. Расписание формировалось для одного изолированного ивента, требуя ручной синхронизации календаря.

**Цель:** Создать единый комплексный конструктор сезонов альянса, позволяющий в 1 клик сгенерировать реалистичный сезон (на 4, 8 или 12 недель) сразу для всех трех событий с настраиваемыми днями недели, продолжительностью, ритмом повторений и интерактивным предпросмотром дат.

---

## 2. Цели, не-цели и анти-цели

### Цели (Goals):
- Удалить шаблон «Сильнейший Командир» из кодовой базы.
- Реализовать три реальных события игры: «Король Войны», «Мощные Силы», «Сила Времени» с преднастроенными игровыми параметрами по умолчанию.
- Поддержать гибкую модель ритма (`Cadence Rule`):
  - День недели старта (Пн–Вс);
  - Длительность в днях;
  - Количество недель активности подряд (`activeWeeks`, e.g. 1 или 2);
  - Количество недель перерыва (`breakWeeks`, e.g. 1 или 2);
  - Смещение стартовой недели (`weekOffset`, Неделя 1 или Неделя 2 для чередования).
- Реализовать интерактивный предпросмотр расписания в модальном окне с возможностью точечного удаления отдельных дат (✕) перед записью в календарь.
- Пакетное сохранение всего сезона через `POST /api/events/schedule-season`.

### Не-цели (Non-Goals):
- Автоматический подсчет очков за конкретные типы ускорителей в «Силе времени» внутри трекера (трекер фиксирует только факт участия сектора, занятое место и полученные купоны).
- Изменение механики ручного добавления единичных событий в календарь (ручное создание остается доступным).

### Анти-цели (Anti-Goals):
- Никаких жестко зашитых нередактируемых дат, которые ломаются при смене игровых правил.
- Не допускать создания сезона без возможности предварительно увидеть точные даты в календаре.

## 3. Рассмотренные варианты реализации (Approaches)

### Вариант 1: Комплексный конструктор сезона с интерактивным предпросмотром (Выбран пользователем)
- В едином окне настраивается дата старта сезона, длительность в неделях и правила для трех ивентов.
- Отображается интерактивный предпросмотр всех создаваемых дат с днями недели и возможностью исключить лишние.
- Сохранение всего сезона одной кнопкой.
- *Почему выбран:* Максимальная прозрачность для руководства альянса, минимум рутины, все три ивента согласованы по неделям без риска наложения.

### Вариант 2: Пресеты с раздельной генерацией по одному ивенту
- Генерация каждого типа ивента отдельно.
- *Почему отклонен:* Требует трижды запускать модалку, вручную отсчитывать недели перерыва и держать в голове календарное чередование.

### Вариант 3: Пошаговый Wizard
- Три экрана: Период ➔ Настройки правил ➔ Предпросмотр.
- *Почему отклонен:* Избыточное количество кликов для регулярной задачи офицеров.

### 4.2. Алгоритм генерации расписания `generateSeasonSchedule` (`logic.js`)
Чистая детерминированная функция:
```javascript
generateSeasonSchedule({
  startDate,      // ISO-строка даты старта сезона (например, '2026-10-27')
  totalWeeks = 8, // Длительность сезона в неделях
  rules = []      // Массив правил для каждого включенного ивента
})
```
Для каждого правила:
- Находится базовый понедельник недели 0.
- Для недели $w \in [0, \text{totalWeeks} - 1]$:
  - Проверяется условие активности:
    $$\text{cycleLen} = \text{activeWeeks} + \text{breakWeeks}$$
    $$\text{relWeek} = (w - \text{weekOffset}) \pmod{\text{cycleLen}}$$
    Если $w \ge \text{weekOffset}$ и $0 \le \text{relWeek} < \text{activeWeeks}$, неделя активна.
  - Дата старта: $\text{monday}(w) + (\text{startDayOfWeek} - 1)$ дней.
  - Дата окончания: $\text{dateFrom} + (\text{durationDays} - 1)$ дней.
  - Запись события: `{ id, typeId, name, dateFrom, dateTo, note, dayFromStr, dayToStr }`.
- Итоговый список сортируется по `dateFrom`.

## 5. Серверный слой (`server.js`, `api.test.js`)

Эндпоинт `POST /api/events/schedule-season`:
- Доступ: `['r4', 'r5']`.
- Принимает:
  - Либо `{ events: [...] }` (отредактированный в предпросмотре список);
  - Либо `{ startDate, totalWeeks, rules }`.
- Обеспечивает существование типов событий в БД (`event_types`):
  - При отсутствии автоматически создает тип с соответствующим именем, цветом и стандартной сеткой наград (1 место: 12500, 2 место: 6500, 3 место: 3500, 4–10 место: 2750 купонов).
- Пакетно сохраняет события через `db.saveEvent` в SQLite.
- Возвращает `{ success: true, count: N, events: [...] }`.

## 6. Пользовательский интерфейс (`index.html`, `app.js`, `style.css`)

### Модальное окно `#modal-season-scheduler`:
1. **Шапка и базовые настройки**:
   - «Дата начала сезона»: поле выбора даты (по умолчанию ближайший понедельник).
   - «Длительность сезона»: кнопки-быстрые пресеты `4 недели`, `8 недель`, `12 недель` + ручной ввод.
2. **Конфигуратор ивентов (3 карточки)**:
   - Чекбокс включения в сезон (все 3 по умолчанию включены).
   - Выбор дня недели старта (Понедельник ... Воскресенье).
   - Длительность (дней).
   - Настройка повтора: «Каждые X нед. активности через Y нед. перерыва».
   - Чередование: «Старт: Неделя 1 / Неделя 2».
3. **Блок интерактивного предпросмотра**:
   - Таблица с колонками: Бейдж ивента, Дата начала (день недели), Дата окончания (день недели), Длительность, Действие (кнопка ✕ для удаления).
   - При изменении любого параметра в карточках таблица предпросмотра мгновенно обновляется.
4. **Подвал**:
   - Кнопка «Отмена».
   - Кнопка «⚡ Создать сезон в календаре (N событий)» — активна, если в предпросмотре есть события.
