## 1. Введение и цели

Данное техническое задание объединяет две взаимосвязанные доработки мобильного интерфейса Telegram Mini App (TMA) и веб-интерфейса KoW Tracker:

1. **Унификация жизненного цикла и статусов игровых событий**:
   - Устранение бага, при котором событие, уже начавшееся по времени, отображается как «Ближайший ивент» и попадает во вкладку «Предстоящие», хотя фактически является **действующим** («Идёт сейчас»).
   - Введение четкого разделения на 3 состояния: **🟢 Действующие (active)**, **◎ Предстоящие (upcoming)**, **◌ Прошедшие (past / completed)**.
   - Синхронизация логики между ядром `shared/logic.js`, веб-интерфейсом `client/app.js`, мобильным клиентом `client/tma.js` и Telegram-ботом `server/bot-controller.js`.

2. **Редизайн вкладки «Матрица» в Telegram Mini App (TMA)**:
   - Устранение несоответствия: в текущей версии TMA во вкладке «Матрица» отображалась временная заглушка — рейтинг секторов по силе со статусом давности склада («🟢 сегодня»).
   - Приведение раздела «Матрица» в TMA к полному функциональному соответствию с веб-версией: отображение **сводной матрицы готовности офицеров** всей гильдии с рекомендациями по местам (🥇 1, 🥈 2, 🥉 3 место, Максимум ✓, Только личные).
   - Адаптация под компактный мобильный экран смартфона с фильтрами, поиском и постраничной загрузкой.

## 2. Часть 1. Жизненный цикл и статусы событий

### 2.1. Единые правила определения статуса события
Все модули системы должны использовать единую функцию классификации событий в `shared/logic.js`:

```javascript
function getEventStatus(event, now = new Date()) {
  if (!event) return 'unknown';
  if (event.status === 'completed') return 'past';

  const currentTime = now instanceof Date ? now.getTime() : new Date(now).getTime();
  const startTime = event.startDate ? new Date(event.startDate).getTime() : null;
  // Если endDate не задан явно, по умолчанию длительность события составляет 3 суток (259200000 мс)
  const durationMs = (Number(event.durationDays) || 3) * 24 * 60 * 60 * 1000;
  const endTime = event.endDate ? new Date(event.endDate).getTime() : (startTime ? startTime + durationMs : null);

  if (startTime && currentTime < startTime) {
    return 'upcoming'; // Еще не началось
  }
  if (startTime && endTime && currentTime >= startTime && currentTime <= endTime) {
    return 'active'; // Идет прямо сейчас
  }
  if (endTime && currentTime > endTime) {
    return 'past'; // Завершилось по времени
  }
  if (event.status === 'active') {
    return 'active';
  }
  return 'upcoming';
}
```

Также реализуется функция пакетной классификации:
```javascript
function classifyEvents(events, now = new Date()) {
  const active = [];
  const upcoming = [];
  const past = [];

  (events || []).forEach(ev => {
    const status = getEventStatus(ev, now);
    if (status === 'active') active.push(ev);
    else if (status === 'upcoming') upcoming.push(ev);
    else past.push(ev);
  });

  // Сортировка:
  // Действующие: сначала те, что закончатся раньше
  // Предстоящие: сначала те, что начнутся раньше
  // Прошедшие: сначала самые свежие (по убыванию даты)
  active.sort((a, b) => new Date(a.startDate || 0) - new Date(b.startDate || 0));
  upcoming.sort((a, b) => new Date(a.startDate || 0) - new Date(b.startDate || 0));
  past.sort((a, b) => new Date(b.endDate || b.startDate || 0) - new Date(a.endDate || a.startDate || 0));

  return { active, upcoming, past };
}
```

### 2.2. Отображение баннера события в Личном Кабинете TMA (`client/tma.js`)
В блоке `renderTmaCabinetEventBanner`:
- **При наличии действующего события (`active.length > 0`)**:
  - Заголовок бейджа: `🟢 Идёт сейчас` (зелёный пульсирующий бейдж).
  - Таймер: «До конца: X дн. Y ч.» (или дата окончания).
  - Название события и офицер.
  - Кнопка действия: «Участвовать / Подробнее ↗».
- **Если действующих нет, но есть предстоящие (`upcoming.length > 0`)**:
  - Заголовок бейджа: `◎ Ближайший ивент`.
  - Дата и обратный отсчет: «Старт через X дн. (ДД.ММ)».
- **Если событий нет**:
  - Блок скрывается либо выводится компактная плашка «Нет запланированных событий».

### 2.3. Вкладка «События» в TMA (`client/tma.js`)
Подвкладки разделяются на 3 категории (вместо текущих двух):
1. `🟢 Действующие (N)`
2. `◎ Предстоящие (N)`
3. `◌ Прошедшие (N)`
По умолчанию открывается вкладка `🟢 Действующие`, если в ней есть хотя бы одно событие. Если действующих нет — открывается `◎ Предстоящие`.

### 2.4. Календарь событий в веб-версии (`client/app.js`)
- Вкладки разделяются на:
  - `🟢 Действующие (N)`
  - `◎ Предстоящие (N)`
  - `◌ Прошедшие (N)`
  - `📑 Все (N)`
- Устраняется объединение `active + upcoming` в одну вкладку «Предстоящие».

## 3. Часть 2. Причина «🟢 сегодня» и редизайн Матрицы в TMA

### 3.1. Анализ проблемы текущей матрицы TMA
- **Что отображалось:**
  В файле `client/tma.js` функция `renderTmaMatrix()` выводила не матрицу офицеров, а список секторов (`state.players`), отсортированных по силе (`p.sector.power`).
- **Откуда взялся статус «🟢 сегодня»:**
  В строках `client/tma.js:1318-1348` рассчитывалась давность обновления запасов склада сектора:
  ```javascript
  const updatedAt = stock.updatedAt || p.updatedAt;
  let daysAgo = 0;
  if (updatedAt) daysAgo = Math.floor((Date.now() - new Date(updatedAt).getTime()) / (1000 * 60 * 60 * 24));
  const isFresh = daysAgo <= 3;
  // Результат:
  isFresh ? '🟢 ' + (daysAgo === 0 ? 'сегодня' : daysAgo + 'д назад') : '🔴 ' + daysAgo + 'д назад'
  ```
  Поскольку данные секторов или склада обновлялись сегодня, у всех строк выводилось значение `🟢 сегодня`.
- **Что должно быть на самом деле:**
  В веб-версии (`client/app.js:9986-10150`) матрица представляет собой **Сводную матрицу готовности офицеров**, где каждая строка — это конкретный офицер игрока, с расчётом дефицита до 180 уровня, медалями, звёздами, складом, прогнозом дней без ивентов и бейджем рекомендации (🥇 1 место, 🥈 2 место, 🥉 3 место, Максимум ✓, Только личные).

### 3.2. Архитектура новой мобильной Матрицы TMA

Для мобильных экранов (ширина 360–430px) стандартная веб-таблица из 11 колонок непригодна. Предлагается мобильный компонент на базе информативных компактных карточек с высокой плотностью данных.

#### 3.2.1. Панель управления и фильтры (верхняя часть)
1. **Поисковая строка**:
   - Полнотекстовый поиск по имени офицера или нику игрока (сектора).
   - Кнопка быстрой очистки (✕).
2. **Чипы быстрого фильтра (горизонтальный скролл)**:
   - **Принадлежность**: `Все офицеры` / `👤 Только мои` (позволяет игроку в один клик увидеть срез по своему сектору).
   - **Род войск**: `Все`, `🛡️ Танк`, `🪖 Пехота`, `🎯 ПТ-САУ`, `🏰 Гарнизон`, `💥 Осада`.
     *(Примечание: Авиация в проекте не отслеживается и полностью исключена из фильтров и расчётов, используются строго 5 типов из `logic.OFFICER_TYPES`).*
   - **Поколение**: `Все`, `G1`, `G2` ... `G9`.
3. **Строка статистики и сортировки**:
   - Счётчик найденных: «Офицеров: 42 (🥇: 6 | 🥈: 8 | ✓: 14)».
   - Дропдаун сортировки:
     - *По дефициту купонов/пазлов* (по умолчанию)
     - *По уровню офицера*
     - *По дням без ивентов*
     - *По имени офицера*
     - *По игроку*

#### 3.2.2. Структура компактной карточки офицера
Каждая карточка содержит:
```
┌────────────────────────────────────────────────────────┐
│ 🛡️ Анхель  [G7]                            🥇 1 место   │
│ 👤 Ranunkulus (Вы)                                     │
├────────────────────────────────────────────────────────┤
│ Ур. 146 / 180  ⭐⭐⭐⭐⭐                             │
│ ────────────────────────────────────────────────────── │
│ 📉 Дефицит: 15 пазл. (7 500 куп.)   📦 Склад: 3 800 🎟️ │
│ ⏱️ Без ивентов: 25 дн. (13 дек)                         │
└────────────────────────────────────────────────────────┘
```

- **Офицеры с личными медалями (например, Анхель)**:
  - Вместо купонов выводится `15 личн. пазл.`.
  - Бейдж рекомендации: `<span class="badge">Только личные</span>` (не может претендовать на купонные призовые места).
- **Офицеры, достигшие максимума (180 ур.)**:
  - Бейдж: `<span class="badge badge-success">Максимум ✓</span>`.
  - Дефицит: `0 пазл.`.
- **Конфиденциальность складов (RBAC)**:
  - Для ролей Р4/Р5 отображаются запасы всех складов.
  - Для роли Р3 чужие склады отображаются как `Скрыто` (в соответствии с функцией `canSeeStock(p.id)`).
- **Интерактивность**:
  - Клик по карточке открывает детальное досье / калькулятор офицера.

#### 3.2.3. Производительность и пагинация
В крупной гильдии может быть 30+ игроков и более 300 офицеров. Для обеспечения плавной работы в Telegram WebApp:
- Карточки рендерятся порциями по 30 штук.
- Внизу списка выводится кнопка «Показать ещё (+30)» или подгрузка при скролле.
