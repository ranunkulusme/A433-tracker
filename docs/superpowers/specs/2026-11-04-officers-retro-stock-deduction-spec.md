## 1. Введение и анализ проблемы

### 1.1. Описание обнаруженного бага
Пользователь зафиксировал следующее некорректное поведение при работе с офицерами:
1. **Сброс режима в модальных окнах:** При добавлении или редактировании офицера выбирается режим **«⚡ Прокачка»**, но после сохранения или при повторном открытии формы выбранным остаётся **«📜 Ретроспектива»**.
2. **Списание со склада в режиме «Ретроспектива»:** Если выбран режим **«📜 Ретроспектива»**, ресурсы со склада (купоны звёзд, легендарные звёзды, медали, купоны) всё равно списываются при изменении звёзд или навыков.
3. **Отсутствие списания при первичном создании с «Прокачкой»:** При создании нового офицера с указанием уровня/звёзд/навыков в режиме «Прокачка» списание со склада вовсе не рассчитывается и не производится.

### 1.2. Анализ причин в кодовой базе
1. **Принудительный сброс радиобаттонов при открытии форм:**
   В [`app.js`](file:///Users/ranunkulus/Downloads/KOW/app.js) в функциях `openAddMyOfficerModal` (стр. 3219), `openEditMyOfficerModal` (стр. 3243), `openAddSectorOfficerModal` (стр. 6456) и `openEditSectorOfficerModal` (стр. 6590) захардкожена строка:
   ```javascript
   retroRadioOn.checked = true; // Принудительно ставит Ретроспективу при каждом открытии
   ```
2. **Игнорирование режима в быстрых действиях карточки и таблицы:**
   Интерактивные звёзды на карточках Личного кабинета ([`setMyOfficerStars`](file:///Users/ranunkulus/Downloads/KOW/app.js#L3410)), кнопки навыков ([`setMyOfficerSkill`](file:///Users/ranunkulus/Downloads/KOW/app.js#L2480)) и звёзды в таблице Сектора ([`handleQuickChangeStars`](file:///Users/ranunkulus/Downloads/KOW/app.js#L6290)) **вообще не проверяют режим списания**. Они безусловно вызывают дельту склада и отправляют запросы `PUT /api/my-profile` / `PUT /api/players/:id`, уменьшая запасы склада.
3. **Пропуск нового офицера в обработчиках модальных окон:**
   В [`saveMyOfficerSubmit`](file:///Users/ranunkulus/Downloads/KOW/app.js#L3264-L3287) расчёт списания обёрнут в `if (myOfficerEditId)`, поэтому при создании нового офицера склад не затрагивается. В [`submitAddSectorOfficer`](file:///Users/ranunkulus/Downloads/KOW/app.js#L6531) и [`submitEditSectorOfficer`](file:///Users/ranunkulus/Downloads/KOW/app.js#L6660) переменная `isRetro` объявляется, но не используется.
4. **Устаревшая разметка:**
   В модальном окне редактирования офицера сектора ([`index.html#L560`](file:///Users/ranunkulus/Downloads/KOW/index.html#L560)) подпись поля звёзд гласит `Звёзды (1-6)` вместо актуального `Звёзды (0-5★)`.

## 3. Детальные требования к функционалу

### 3.1. Глобальный тумблер режима склада на страницах
1. **Размещение тумблера:**
   - **Личный кабинет (`#page-my-cabinet`):** В шапке секции «Командиры» рядом с кнопкой «+ Добавить офицера».
   - **Карточка Сектора (`renderPlayerDetail`):** В шапке таблицы «Офицеры сектора» рядом с кнопкой добавления офицера.
2. **Виджет тумблера (Segmented Control / Switcher):**
   - Две взаимоисключающие кнопки:
     - `📜 Ретро-режим` — подсказка: *«Изменение параметров без списания со склада (ввод существующего офицера)»*.
     - `⚡ Прокачка` — подсказка: *«Списывать купоны, звёзды и медали со склада трекера»*.
   - Активная кнопка выделяется цветом (акцентный синий/янтарный).
3. **Хранение состояния тумблера:**
   - Состояние сохраняется в `localStorage.getItem('kow_officer_stock_mode')` (значения `'retro'` или `'normal'`).
   - По умолчанию при первом открытии: `'retro'` (защита от случайных нежелательных списаний склада).
   - При смене положения тумблера состояние мгновенно применяется ко всем карточкам текущего экрана без перезагрузки страницы.

### 3.2. Логика быстрых действий на карточках офицеров

#### 3.2.1. Клик по интерактивным звёздам:
* **Функции:** `setMyOfficerStars(officerId, stars)` (Кабинет) и `handleQuickChangeStars(playerId, officerId, stars)` (Сектор).
* **Алгоритм:**
  1. Считать текущий режим: `const mode = getOfficerStockMode();` (`'retro'` или `'normal'`).
  2. Если `mode === 'retro'`:
     - **Склад НЕ трогаем:** `newStock = null`, `stockDelta = null`.
     - Запрос на бэкенд обновляет только звёзды: `PUT /api/.../officers/:id` с `{ stars: newStars }`.
     - `officer.invested` не изменяется.
     - Выводится тост: `⭐ Звёзды офицера обновлены (Ретро: без списания со склада)`.
  3. Если `mode === 'normal'`:
     - Проверяется достаточность звёзд и купонов звёзд на складе через `calculateStarStockDelta`.
     - Если ресурсов недостаточно — операция отклоняется, выводится тост с суммой дефицита.
     - Если ресурсов достаточно — списываются ресурсы со склада, фиксируется `officer.invested`, выводится тост с возможностью отката `[↩ Отменить]`.

#### 3.2.2. Клик по уровням навыков (Н1..Н4):
* **Функция:** `setMyOfficerSkill(officerId, skillIndex, level)` (Кабинет).
* **Алгоритм:**
  1. Считать текущий режим: `const mode = getOfficerStockMode();`.
  2. Если `mode === 'retro'`:
     - **Склад НЕ трогаем:** `newStock = null`, `stockDelta = null`.
     - Запрос на бэкенд обновляет только навыки: `PUT /api/my-profile/officers/:id` с `{ skills: newSkills }`.
     - Выводится тост: `🎯 Навык N обновлен: Lvl/5 (Ретро: без списания со склада)`.
  3. Если `mode === 'normal'`:
     - Рассчитывается расход купонов и универсальных медалей через `calculateSkillStockDelta`.
     - При нехватке — отмена с сообщением об ошибке.
     - При успехе — списание со склада с фиксацией в `officer.invested` и кнопкой отмены `[↩ Отменить]`.

### 3.3. Модальные окна добавления и редактирования

1. **Инициализация радиокнопок при открытии:**
   - При вызове `openAddMyOfficerModal`, `openEditMyOfficerModal`, `openAddSectorOfficerModal`, `openEditSectorOfficerModal`:
     Удалить жесткую привязку `retroRadioOn.checked = true`.
     Радиокнопка выставляется в соответствии с **текущим выбранным режимом тумблера** (`mode === 'normal' ? offRadio.checked = true : onRadio.checked = true`).
   - Пользователь при желании может точечно переключить радиобаттон в самом модальном окне перед нажатием «Сохранить».

2. **Создание нового офицера (`POST /api/.../officers`):**
   - Если в модалке выбрано **«⚡ Прокачка»** (`!isRetro`):
     1. Если указан `level > 0`, `stars > 0` или `skills` выше базовых `[1, 1, 1, 1]`:
     2. Вычисляется суммарная потребность в ресурсах склада:
        - По уровню: `calculateLevelStockDelta(0, level, stock, costPerPuzzle, upgradeType)`
        - По звёздам: `calculateStarStockDelta(0, stars, stock, starCouponCost, null)`
        - По навыкам: `calculateSkillStockDelta([1,1,1,1], skills, stock, costPerPuzzle, upgradeType, maxMedals, null)`
     3. Если хотя бы по одному типу ресурсов выявлен дефицит (`!delta.canAfford`):
        - Прервать операцию.
        - Вывести предупреждение пользователю: *«❌ Недостаточно ресурсов на складе для прокачки офицера: (указать чего именно не хватает). Добавление отменено.»*
     4. Если ресурсов достаточно:
        - Единым пакетом списать ресурсы со склада игрока.
        - Сохранить офицера с заполненным объектом `invested`.
        - Показать тост: *«Офицер добавлен, ресурсы списаны со склада»*.
   - Если в модалке выбрано **«📜 Ретроспектива»** (`isRetro`):
     - Никакие списания со склада не производятся.
     - Офицер создается с `invested = { starCoupons: 0, legendaryStars1: 0, legendaryStars2: 0, legendaryStars3: 0, coupons: 0, puzzles: 0 }`.

3. **Редактирование офицера (`PUT /api/.../officers/:id`):**
   - В Личном кабинете ([`saveMyOfficerSubmit`](file:///Users/ranunkulus/Downloads/KOW/app.js#L3250)) и в Секторе ([`submitEditSectorOfficer`](file:///Users/ranunkulus/Downloads/KOW/app.js#L6654)):
     - При `isRetro === true`: гарантировать, что ни склад, ни `officer.invested` не изменяются при любых правках уровня, звёзд или навыков.
     - При `isRetro === false`: рассчитывать дельту склада по уровню, звёздам и навыкам, проверять баланс и списывать только фактическую разницу.

4. **Правка разметки в [`index.html#L560`](file:///Users/ranunkulus/Downloads/KOW/index.html#L560):**
   - Заменить ошибочную метку `<label>Звёзды (1-6)</label>` на `<label>Звёзды (0-5★)</label>`.
