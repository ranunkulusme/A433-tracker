# Спецификация: Гибкая настройка расписания событий в Типах ивентов и динамический Конструктор сезонов

**Дата:** 2026-10-31  
**Версия релиза:** v3.18.0  
**Статус:** Согласовано  

---

## 1. Контекст и цели

### 1.1. Проблема
В текущей версии генератора сезонов альянса (`#modal-season-scheduler`):
1. **Жесткая зашитость карточек:** В HTML-разметке и скрипте зашиты ровно 3 карточки событий: «Король Войны», «Мощные Силы» и «Сила Времени». Добавить новое периодическое событие (например, добавленное разработчиками игры Kiss of War или внутригильдейский ивент) невозможно без изменения исходного кода.
2. **Селектор длительности вместо дней недели:** Длительность задается выбором абстрактного количества дней (`2 дня`, `3 дня`), тогда как в игре события привязаны к конкретным дням недели (например, со вторника по среду, с субботы по понедельник, со вторника по четверг).
3. **Разрыв между «Типами ивентов» и Генератором сезонов:** В приложении существует справочник «Типы ивентов» (`event_types`), где хранятся цвета и награды за места, однако параметры периодичности (дни старта/окончания, ритм и смещение) были оторваны от справочника и захардкожены в генераторе.
4. **Трудоёмкое обновление наград при выходе нового поколения офицеров:** Когда в игре появляется новое поколение (Gen 8, Gen 9...), разработчики Kiss of War повышают призовые купоны во всех ивентах сразу. Сейчас лидеру приходится вручную открывать каждый тип ивента и по отдельности перебивать значения для каждого призового места.

### 1.2. Цели
1. **Хранение расписания в «Типах ивентов»:** Перенести параметры периодичности событий (день начала, день окончания, ритм активности, смещение недели, флаг участия в генераторе) в справочник `event_types`.
2. **Указание длительности через «День начала» и «День окончания»:** В интерфейсе типа ивента и генератора указывать день начала (Пн–Вс) и день окончания (Пн–Вс) с автоматическим вычислением длительности и поддержкой перехода через выходные (например, Суббота ➔ Понедельник = 3 дня).
3. **Динамический Конструктор сезонов:** Убрать статичные карточки из HTML. Генератор сезонов динамически загружает все периодические типы событий из базы данных, позволяет добавлять новые типы событий на лету, изменять их параметры для конкретного сезона и генерировать расписание.
4. **Механизм массового обновления наград за 1 клик:** Реализовать пакетное обновление наградной сетки мест сразу для всех выбранных типов ивентов (модальное окно `#modal-bulk-rewards` и эндпоинт `POST /api/event-types/bulk-rewards`).
5. **Личные пазлы офицера (`personalPuzzles`):** Добавить в модель офицера параметр именных личных пазлов, которые можно потратить только на данного офицера. Личные пазлы учитываются в прогрессе и в первую очередь уменьшают персональный дефицит командира до 180 уровня.

## 2. Архитектура и модель данных

### 2.1. Изменения схемы БД SQLite (`db.js`)
Таблица `event_types` расширяется полями расписания:
```sql
ALTER TABLE event_types ADD COLUMN is_periodic INTEGER NOT NULL DEFAULT 1;
ALTER TABLE event_types ADD COLUMN start_day_of_week INTEGER NOT NULL DEFAULT 2;
ALTER TABLE event_types ADD COLUMN end_day_of_week INTEGER NOT NULL DEFAULT 3;
ALTER TABLE event_types ADD COLUMN active_weeks INTEGER NOT NULL DEFAULT 1;
ALTER TABLE event_types ADD COLUMN break_weeks INTEGER NOT NULL DEFAULT 1;
ALTER TABLE event_types ADD COLUMN week_offset INTEGER NOT NULL DEFAULT 0;
```

Таблица `player_officers` расширяется полем личных пазлов:
```sql
ALTER TABLE player_officers ADD COLUMN personal_puzzles INTEGER NOT NULL DEFAULT 0;
```

#### Стандартные начальные данные (`initDb`):
1. **Король Войны:**
   - `start_day_of_week: 2` (Вторник)
   - `end_day_of_week: 3` (Среда)
   - `active_weeks: 1`, `break_weeks: 1`, `week_offset: 0`
   - `color: '#8b5cf6'`, `is_periodic: 1`
2. **Мощные Силы:**
   - `start_day_of_week: 6` (Суббота)
   - `end_day_of_week: 1` (Понедельник — переход через выходные)
   - `active_weeks: 1`, `break_weeks: 1`, `week_offset: 0`
   - `color: '#10b981'`, `is_periodic: 1`
3. **Сила Времени:**
   - `start_day_of_week: 2` (Вторник)
   - `end_day_of_week: 4` (Четверг)
   - `active_weeks: 1`, `break_weeks: 1`, `week_offset: 1` (чередование со 2-й недели)
   - `color: '#f59e0b'`, `is_periodic: 1`

### 2.2. Чистая бизнес-логика (`logic.js`)

#### Формула расчета длительности по дням недели:
```javascript
function calculateDurationDays(startDay, endDay) {
  const s = Math.max(1, Math.min(7, Number(startDay) || 1));
  const e = Math.max(1, Math.min(7, Number(endDay) || 1));
  if (e >= s) {
    return e - s + 1;
  }
  // Переход через воскресенье в понедельник:
  return (7 - s) + e + 1;
}
```
*Примеры:*
- Вторник (2) ➔ Среда (3): $3 - 2 + 1 = 2$ дня.
- Вторник (2) ➔ Четверг (4): $4 - 2 + 1 = 3$ дня.
- Суббота (6) ➔ Понедельник (1): $(7 - 6) + 1 + 1 = 3$ дня (Сб, Вс, Пн).
- Пятница (5) ➔ Воскресенье (7): $7 - 5 + 1 = 3$ дня (Пт, Сб, Вс).
- Понедельник (1) ➔ Понедельник (1): $1 - 1 + 1 = 1$ день.

#### Функция `generateSeasonSchedule`:
Принимает массив правил `rules`, где каждое правило может содержать либо `durationDays`, либо пару `startDayOfWeek` + `endDayOfWeek`. Длительность и строковые метки дней (`dayFromStr`, `dayToStr`) вычисляются автоматически.

#### Расчет дефицита с учетом личных пазлов (`calculateOfficerDeficit`):
```javascript
const personalPuzzles = Math.max(0, Number(officer?.personalPuzzles || officer?.personal_puzzles) || 0);
const currentPuzzles = officerLevel * PUZZLES_PER_LEVEL
  + (costPerPuzzle > 0 ? Math.floor(officerCoupons / costPerPuzzle) : 0)
  + personalPuzzles;
const deficitPuzzles = Math.max(0, targetPuzzles - currentPuzzles - stockPuzzles);
```
Личные пазлы:
- Сразу уменьшают дефицит конкретного офицера.
- Отображаются в прогресс-баре готовности офицера.
- Приоритетно закрывают уровень перед тратой общих пазлов склада (`stock.puzzles`).

## 3. Пользовательский интерфейс (UI)

### 3.1. Модальное окно редактирования типа ивента (`#modal-et`)
В форму добавляется блок:
1. **Чекбокс:** `Периодическое событие сезона (участвует в генераторе)`
2. **Селекторы дней:**
   - `День начала`: выпадающий список (Понедельник ... Воскресенье).
   - `День окончания`: выпадающий список (Понедельник ... Воскресенье).
   - Интерактивный бейдж с вычисленной длительностью: `2 дня (Вт–Ср)`.
3. **Параметры ритма:**
   - `Ритм активности`: `X нед. акт. / Y нед. перерыв`.
   - `Смещение недели`: `Неделя 1 (без смещения)`, `Неделя 2 (со 2-й недели)` и т.д.

### 3.2. Страница «Типы ивентов» (`#et-list`)
В карточке типа ивента отображается плашка периодичности:
`📅 Вт–Ср (2 дня) · Ритм: 1 нед. через 1 (Неделя 1) · Сезонный`

### 3.3. Конструктор сезонов альянса (`#modal-season-scheduler`)
1. Вместо статичных карточек — контейнер `#season-event-cards`, который динамически заполняется карточками из `state.eventTypes.filter(et => et.isPeriodic)`.
2. Над сеткой карточек располагается кнопка **«+ Добавить тип события»**. Клик открывает модальное окно `#modal-et` для создания нового события. После сохранения оно моментально появляется в конструкторе.
3. Каждая карточка содержит:
   - Чекбокс включения в текущий сезон.
   - Название, иконку и цветную полосу типа события.
   - Селекторы: «День начала» и «День окончания» с бейджем длительности.
   - Поля ритма активности и смещения.
   - Кнопку скрытия/удаления карточки из текущей генерации.
4. Таблица интерактивного предпросмотра снизу мгновенно обновляет расписание при любых изменениях.

---

### 3.4. Массовое обновление наград во всех ивентах (`#modal-bulk-rewards`)
1. На странице «Типы ивентов» рядом с кнопкой `+ Добавить тип` появляется кнопка: **«⚡ Массовое обновление наград»**.
2. Модальное окно содержит:
   - Подсказку о назначении: *«Используйте при выходе нового поколения офицеров для одновременного повышения наград во всех событиях»*.
   - Интерактивную сетку призовых мест (1 место, 2 место, 3 место, 4–10 место...) с полями ввода количества купонов (награды задаются строго в купонах, так как курс пазлов зависит от поколения конкретного офицера игрока: 500, 600 или 720).
   - Список типов ивентов с чекбоксами (по умолчанию выбраны все периодические события).
   - Кнопку: **«✓ Применить ко всем выбранным ивентам»**.
3. На странице «Типы ивентов» в карточках событий убирается устаревшая статичная колонка «Пазлов» (рассчитывавшаяся по фиксированному курсу 500), оставляя точные призовые купоны.
4. На бэкенде: эндпоинт `POST /api/event-types/bulk-rewards` атомарно в транзакции SQLite обновляет `places_json` (и сохраняет запись в `prize_history_json`) для всех выбранных типов ивентов.

### 3.5. Отображение и редактирование личных пазлов офицера
1. **В модальном окне Личного кабинета (`#modal-my-officer`):**
   - Строка уровня преобразуется в трёхколоночную сетку `form-row form-row-3`:
     - `Уровень (0-180)` (`#my-officer-level`)
     - `Купоны на уровне` (`#my-officer-coupons`)
     - `🧩 Личные пазлы` (`#my-officer-personal-puzzles`)
   - Подсказка: *«Именные пазлы конкретного офицера, уменьшающие дефицит подготовки только для него»*.
2. **В модальных окнах сектора (`#modal-add-sector-officer` и `#modal-sector-officer`):**
   - Точно так же блок уровня преобразуется в компактную строку из 3 полей:
     - `Уровень (0-180)` (`#aso-level` / `#so-level`)
     - `Вложено купонов` (`#aso-coupons` / `#so-coupons`)
     - `🧩 Личные пазлы` (`#aso-personal-puzzles` / `#so-personal-puzzles`)
3. **В карточке офицера в Личном кабинете (`renderCabinetOfficerCardHtml`):**
   - Над прогресс-баром выводится строка со всеми тремя метриками:
     `Уровень: 45 / 180` · `🧩 Пазлы: 15` (если $>0$, выделяется цветом `var(--blue)`) · `Купоны: 1 200`.
   - Прогресс-бар `currPuz / targetPuz` рассчитывается с учетом личных пазлов.
   - Дефицит до 180 уровня уменьшается на количество личных пазлов.
4. **В таблице офицеров сектора (`renderPlayerDetail`):**
   - Дефицит и даты прогноза рассчитываются с точным вычетом личных пазлов офицера.

## 4. Безопасность и RBAC
- Просмотр типов ивентов доступен всем авторизованным пользователям.
- Добавление, редактирование, удаление типов ивентов, массовое обновление наград и генерация сезонов строго ограничены ролями **R4** и **R5** (для R3 возвращается `403 Forbidden`).
