## 1. Введение и анализ замечаний пользователя

По результатам проверки релиза **v3.15.0** сформированы три задачи по улучшению пользовательского интерфейса:

### 1.1. Скриншот 1 (Личный кабинет: блок «Параметры сектора»)
- **Симптом:** Числа в полях ввода отображаются сплошным неформатированным массивом цифр:
  - «Очки VIP»: `629500` *(требуется: `629 500`)*
  - «Мощь / Сила»: `158204982` *(требуется: `158 204 982`)*
  - «Убито»: `84778531` *(требуется: `84 778 531`)*
  - «Очки за убийство»: `7588165023` *(требуется: `7 588 165 023`)*
- **Причина:** Использование атрибута `<input type="number">`. Браузеры по спецификации HTML5 запрещают наличие пробелов и любых разделителей в значениях числовых полей ввода. Передача форматированной строки вида `"158 204 982"` в `input.value` поля `type="number"` сбрасывается браузером в пустоту либо игнорируется.
- **Масштаб проблемы:** Аналогичная проблема присутствует во всех формах ввода параметров сектора:
  1. Блок «Параметры сектора» в Личном кабинете (`renderMyCabinet`).
  2. Модальное окно редактирования сектора / игрока (`#modal-player` -> поля `fp-power`, `fp-kills`, `fp-kill-points`, `fp-vip-points`).
  3. Модальное окно добавления сектора (`#modal-add-sector` -> поля `as-power`, `as-kills`).
  4. Форма предпросмотра сканера OCR (`#modal-smart-scanner` -> поля `scanner-preview-power`, `scanner-preview-kills`, `scanner-preview-kill-points`).

### 1.2. Скриншот 2 (Страница «Сектор»: таблица «Офицеры сектора»)
- **Симптом:** При наведении курсора на звёзды офицеров в колонке «ЗВЁЗДЫ» на странице «Сектор» (`renderPlayerDetail`) отсутствует стилизованная всплывающая подсказка с точной стоимостью уровня звёзд, а также нет вспомогательной текстовой плашки стоимости, как в Личном кабинете.
- **Причина:**
  1. В функции `renderSectorOfficerStars` для кнопок звёзд формировался только нативный HTML-атрибут `title="..."`, но отсутствовал атрибут `data-tooltip="..."`. Кастомные стили тултипов `.star-btn[data-tooltip]::after` работают исключительно при наличии `data-tooltip`.
  2. В режиме чтения `renderStars` использовался элемент `<span class="star-readonly">`, который не поддерживает кастомные тултипы.
  3. В модальных окнах добавления офицера сектора (`#modal-add-sector-officer`) и редактирования офицера (`#modal-sector-officer`) пикеры звёзд (`aso-stars-picker`, `so-stars-picker`) также не имели `data-tooltip` и подсказок стоимости.
  4. В ячейке таблицы отсутствует компактная строка-подсказка текущего уровня звёзд и стоимости следующего апа.
  5. При клике по звезде в таблице сектора (`handleQuickChangeStars`) вызывался `renderPlayerDetail(playerId)`, приводящий к полной перезагрузке всей страницы сектора.

### 1.3. Расположение версии приложения в сайдбаре
- **Требование пользователя:** Версию приложения оставить **только в нижней части** сайдбара (в футере). Из верхней части сайдбара (рядом с логотипом) бейдж версии убрать, чтобы не загромождать верхнюю панель брендинга.

### 1.4. Скриншот 3 (Персональный симулятор прокачки: аномалия 3 854 / 900 и учет поколений)
- **Симптом:** В блоке «Прогресс до цели (Ур. 180)» выводится странное значение: `100% (3 854 / 900 пазлов)`.
- **Причины:**
  1. **Слепое суммирование без ограничения целью:** Симулятор складывает уже вкачанные пазлы офицера Лиоры (900) со всеми складскими ресурсами сектора (2 954) без ограничения максимумом цели (`targetPuz = 900`), выдавая $900 + 2\,954 = 3\,854$ пазла (428% от цели).
  2. **Игнорирование стоимости купонов по поколениям офицеров:** В симуляторе для конвертации купонов в пазлы захардкожен курс `COUPON_PER_PUZZLE = 500`. Однако Лиора относится к **7-му поколению (Ген. 7)**, где стоимость пазла в игре составляет **600 купонов** (для Ген. 8+ — 720 купонов, для специальных офицеров — 0 / только медали). При конвертации 433 602 купонов по курсу Лиоры получается $433\,602 / 600 = 722$ пазла, а суммарный запас склада равен $2\,087 + 722 = 2\,809$ пазлов (а не 2 954).
  3. В карточках призовых мест ивентов в симуляторе призовые купоны также переводятся в пазлы по константе 500 вместо индивидуального курса выбранного офицера.

### 1.5. Скриншот 4 (Карточка офицера: реальная сквозная шкала прокачки навыков до подготовки)
- **Фактическая механика игры (подтверждена скриншотом пользователя):**
  Прокачка навыков офицера до подготовки представляет собой **16 последовательных шагов** (по 4 шага на каждый из 4 навыков с 1 по 5 уровень) со **сквозной возрастающей стоимостью**:
  `[10, 10, 15, 15, 30, 30, 40, 40, 45, 45, 50, 50, 75, 75, 80, 80]`.
- **Сумма всех 16 шагов в точности равна 690 медалям:**
  $$10+10+15+15+30+30+40+40+45+45+50+50+75+75+80+80 = \mathbf{690} \text{ медалей!}$$
- **Ошибка предыдущей реализации:**
  В старом коде ошибочно предполагалось, что каждый отдельный навык имеет свою фиксированную изолированную стоимость (`[100, 200, 240, 150]`), тогда как в реальной игре стоимость возрастает сквозным образом по мере общего числа апов навыков.
- **Требование:**
  Реализовать точный расчёт затрат медалей по сквозной 16-ступенчатой шкале игры с поддержкой динамического потолка из карточки каталога (`cat.medalsBeforeTraining`, базово 690).

## 2. Детальные требования к реализации

### Задача 1. Форматирование чисел в полях ввода (Live Space-Separated Number Inputs)

#### 1.1. Замена типа полей ввода в HTML
Все поля ввода больших чисел должны быть переведены с `type="number"` на текстовые поля с поддержкой цифровой клавиатуры на мобильных устройствах:
- Для целых чисел (сила, киллы, очки VIP, купоны, пазлы):
  ```html
  <input type="text" inputmode="numeric" pattern="[0-9 ]*" autocomplete="off">
  ```
- Для дробных чисел (очки за убийство):
  ```html
  <input type="text" inputmode="decimal" autocomplete="off">
  ```

#### 1.2. Универсальные утилиты форматирования и парсинга (`logic.js` / `app.js`)
В `logic.js` (с покрытием юнит-тестами) и `app.js` добавляются функции:
1. `formatInputNumber(val, allowDecimals = false)`:
   - Преобразует число или строку с цифрами в вид с разделителем-пробелом: `158204982` $\to$ `158 204 982`.
   - Для дробных чисел сохраняет десятичную часть через точку или запятую: `7588165023.5` $\to$ `7 588 165 023,5`.
2. `parseInputNumber(str, allowDecimals = false)`:
   - Удаляет все пробелы и нечисловые символы: `"158 204 982"` $\to$ `158204982`.
   - Корректно возвращает `0`, если строка пустая.
3. `bindNumericFormatting(inputEl, allowDecimals = false)`:
   - Обработчик события `input`: очищает недопустимые символы, форматирует значение с пробелами и восстанавливает корректное положение текстового курсора (caret position), предотвращая скачки курсора в конец поля.

#### 1.3. Применение на всех экранах приложения
- **Личный кабинет (`renderMyCabinet`)**:
  - `#my-sector-vip-points`: начальное значение `formatInputNumber(profile.sector.vipPoints)`.
  - `#my-sector-power`: начальное значение `formatInputNumber(profile.sector.power)`.
  - `#my-sector-kills`: начальное значение `formatInputNumber(profile.sector.kills)`.
  - `#my-sector-kill-points`: начальное значение `formatInputNumber(profile.sector.killPoints, true)`.
  - В обработчиках сохранения `saveMySector()` и `saveMyCabinetProfile()` парсинг значений через `parseInputNumber`.
- **Модальное окно сектора (`#modal-player`)**:
  - Поля `#fp-vip-points`, `#fp-power`, `#fp-kills`, `#fp-kill-points` заполняются через `formatInputNumber`.
  - В функции `savePlayer()` чтение значений через `parseInputNumber`.
- **Модальное окно добавления сектора (`#modal-add-sector`)**:
  - Поля `#as-power`, `#as-kills` форматируются пробелами.
- **Smart Scanner (`#modal-smart-scanner`)**:
  - Поля предпросмотра сканера `#scanner-preview-power`, `#scanner-preview-kills`, `#scanner-preview-kill-points` заполняются с пробелами.

### Задача 4. Корректный расчёт симулятора прокачки с учётом поколения офицера и отображение профицита

#### 4.1. Расчёт стоимости пазла в купонах строго по поколению офицера
Стоимость пазла офицера в купонах (`couponPerPuzzle` / `costPerPuzzle`) определяется параметрами каталога и поколением офицера:
- **Поколения 1–6 (стандартные):** `500` купонов за 1 пазл.
- **Поколение 7 (например, Лиора, Генерал Рекс, Капитан Блэк):** `600` купонов за 1 пазл.
- **Поколение 8+ (например, Адмирал Нейтон, Аврора, Валькирия):** `720` купонов за 1 пазл.
- **Специальные офицеры (`upgradeType = 'special'`, Ангел, Грейс, Халина и др.):** `0` купонов (купоны не применяются, офицер прокачивается исключительно за медали).

В `app.js` (`renderCabinetSimulatorHtml`):
1. Определение `cat = getCatalogOfficer(selectedOfficer.catalogId)` с корректным разрешением стоимости:
   ```javascript
   const rawCost = Number(cat?.couponPerPuzzle);
   const costPerPuzzle = rawCost === 0
     ? (cat?.upgradeType === 'special' ? 0 : 500)
     : (rawCost || (cat?.generation === 7 ? 600 : (cat?.generation >= 8 ? 720 : 500)));
   ```
2. Конвертация купонов склада для выбранного офицера:
   ```javascript
   const stockMedals = Math.max(0, Number(myCabinetProfile.stock?.puzzles) || 0);
   const stockCoupons = Math.max(0, Number(myCabinetProfile.stock?.coupons) || 0);
   const stockPuzzlesFromCoupons = costPerPuzzle > 0 ? Math.floor(stockCoupons / costPerPuzzle) : 0;
   const totalStockPuzzlesForOfficer = stockMedals + stockPuzzlesFromCoupons;
   ```
3. Конвертация призовых купонов в карточках ивентов:
   - В карточках 1, 2, 3 и 4–10 мест приписка `(+N пазл.)` рассчитывается исходя из `costPerPuzzle` выбранного офицера:
     `Math.floor(placeCoupons / costPerPuzzle)`.
   - Если для спец-офицера `costPerPuzzle === 0`, выводится `(только купоны на склад)`.

#### 4.2. Ограничение числителя прогресс-бара потолком цели
- Числитель шкалы прогресса не может превышать 100% цели (`targetPuz`):
  ```javascript
  const effectivePuzzles = Math.min(targetPuz, currentPuzTotal + sim.puzzlesFromEvents);
  ```
- Для офицера максимального 180 уровня (Лиора) строка прогресса отображает строго:
  **`100% (900 / 900 пазлов)`** вместо абсурдных `3 854 / 900`.

#### 4.3. Наглядная плашка профицита/остатка ресурсов склада
Прямо под полосой прогресса размещается строка с детализацией складских запасов под конкретное поколение:
- **Если дефицит офицера = 0 (офицер готов):**
  ```html
  <div class="sim-stock-surplus-note">
    📦 Доступно на складе: <strong>${fmtNum(totalStockPuzzlesForOfficer)} пазл.</strong>
    <span class="text-muted">(избыток +${fmtNum(totalStockPuzzlesForOfficer)} пазл. сверх цели)</span>
    <span class="sim-stock-detail-hint" title="Медали: ${fmtNum(stockMedals)} шт. + Купоны: ${fmtNum(stockCoupons)} шт. (по курсу ${costPerPuzzle} куп./пазл)">ℹ️</span>
  </div>
  ```
- **Если офицер ещё прокачивается (дефицит > 0):**
  - Показывается, сколько пазлов покрыто со склада и сколько остаётся свободных ресурсов.

### Задача 5. Точный расчёт затрат на навыки офицера по сквозной 16-ступенчатой шкале

#### 5.1. Реальная шкала прокачки навыков игры (16 шагов на увеличение)
В игре Kiss of War / Sea War: Raid 4 навыка офицера прокачиваются от 1 до 5 уровня (всего 16 улучшений). Стоимость каждого последующего улучшения строго возрастает по сквозному ряду:
```javascript
const SKILL_PROGRESSION_COSTS = [
  10, 10, 15, 15, 30, 30, 40, 40, 45, 45, 50, 50, 75, 75, 80, 80
];
```
Сумма всех 16 элементов шкалы:
$$10 + 10 + 15 + 15 + 30 + 30 + 40 + 40 + 45 + 45 + 50 + 50 + 75 + 75 + 80 + 80 = \mathbf{690} \text{ медалей!}$$

#### 5.2. Алгоритм расчёта фактически вложенных медалей
1. Для текущей конфигурации навыков `[s1, s2, s3, s4]` вычисляется общее число сделанных улучшений:
   $$\text{totalUpgrades} = (s_1 - 1) + (s_2 - 1) + (s_3 - 1) + (s_4 - 1) \quad (\text{от 0 до 16}).$$
2. Потраченные медали рассчитываются как сумма первых `totalUpgrades` элементов ряда `SKILL_PROGRESSION_COSTS`:
   - 0 апов (`1-1-1-1`): **0 медалей** (осталось 690).
   - 4 апа (`5-1-1-1`): $10+10+15+15 = \mathbf{50}$ медалей.
   - 8 апов (`5-5-1-1`): $50 + 30+30+40+40 = \mathbf{190}$ медалей.
   - 12 апов (`5-5-5-1`): $190 + 45+45+50+50 = \mathbf{380}$ медалей.
   - 16 апов (`5-5-5-5`): $380 + 75+75+80+80 = \mathbf{690}$ медалей (**MAX**).
3. Потолок стоимости считывается из карточки офицера каталога (`cat.medalsBeforeTraining`, базовое значение 690). Если в каталоге задано иное значение, расчёт пропорционально адаптируется.

#### 5.3. Обновление функции в `logic.js` и интерфейса в `app.js`
1. Сигнатура функции в `logic.js`:
   ```javascript
   function calculateSkillMedalsProgress(skills = [1, 1, 1, 1], maxMedals = 690)
   ```
   Возвращает:
   ```javascript
   {
     spentMedals,          // точная сумма по сквозному ряду (напр. 690 при 5-5-5-5)
     totalMedals,          // 690 (или значение из карточки каталога)
     remainingMedals,      // 690 - spentMedals
     isMaxSkills,          // true, если spentMedals === totalMedals
     skills                // [s1, s2, s3, s4]
   }
   ```

### Задача 6. Механизм автоматического списания и возврата запасов склада при прокачке офицера

#### 6.1. Строгий приоритет списания: «Сначала купоны — затем звёзды и медали»
Для сохранения более ценных и универсальных предметов (медалей и звёзд) действует строгий приоритет:
1. **Прокачка звёзд офицера (0★ ➔ 6★):**
   - **1-й приоритет (в первую очередь):** Списываются **Купоны звезды** (`stock.starCoupons`), конвертируемые в очки звёзд по курсу каталога `starCouponCost` за пакет из 110 звёзд (например, 360 купонов за 110 очков для Ген. 8, 300 для Ген. 7, 250 для Ген. 6).
   - **2-й приоритет (во вторую очередь):** Только если купонов звезды не хватило для закрытия требуемой суммы очков, списываются **готовые Звёзды со склада** в порядке убывания номинала: Звёзды III (960) $\to$ Звёзды II (420) $\to$ Звёзды I (110).
   - **Возврат при понижении звёзд:** На склад возвращаются потраченные ресурсы в обратном порядке (сначала восстанавливаются звёзды, затем купоны).
2. **Прокачка подготовки / уровней (1..180 ур.):**
   - **1-й приоритет (в первую очередь):** Складские **Купоны офицера** (`stock.coupons`) по индивидуальному курсу поколения офицера (`cat.couponPerPuzzle`, напр. 600 для Ген. 7 Лиоры, 720 для Ген. 8, 500 для Ген. 1–6). Рудиментное поле «Личные купоны офицера» исключается из цепочки списания, так как в реальной игре все купоны хранятся исключительно на общем складе сектора.
   - **2-й приоритет (только если купонов на складе не хватило):** Списываются универсальные **Медали офицера со склада** (`stock.puzzles`).
   - **Возврат при понижении уровня:** На склад возвращаются потраченные ресурсы в обратном порядке (сначала восстанавливаются медали, затем купоны).
3. **Прокачка навыков (до подготовки):**
   - **1-й приоритет:** Купоны офицера со склада (по курсу поколения, для стандартных офицеров).
   - **2-й приоритет:** Медали офицера (`stock.puzzles`). Для специальных офицеров (`upgradeType = 'special'`) списываются исключительно медали.
   - **Возврат при понижении навыков:** Возврат ресурсов на склад.

#### 6.2. Защита баланса и интерфейсные контроли
1. **Проверка достаточности ресурсов (Защита от ухода в минус):**
   - Если на складе суммарно недостаточно ресурсов для перехода на выбранный уровень, операция отклоняется:  
     *«❌ Недостаточно ресурсов на складе! Требуется 25 000 звёзд. Доступно: 12 000 звёзд (не хватает 13 000). Повышение отменено.»*
2. **Тумблер режима: «Связь со складом (ВКЛ / ВЫКЛ)»:**
   - **ВКЛ (по умолчанию):** Любые клики по звёздам, навыкам и уровням сразу списывают/возвращают ресурсы на складе с мгновенным обновлением плашек запасов.
   - **ВЫКЛ (режим примерки/симуляции):** Позволяет тестировать прокачку офицеров без изменения фактических запасов склада.
3. **Кнопка быстрой отмены транзакции в тосте:**  
   После успешной прокачки показывается тост с кнопкой:  
   *«⭐ Звёзды Лиоры: 4★. Списано: 69 444 купонов звезды (-25 000 очков). [↩ Отменить]»*.
4. **Журнал истории склада:**  
   Каждая операция списания и возврата фиксируется в массиве `stockHistory` сектора с меткой времени, офицером и детализацией дельты ресурсов.
